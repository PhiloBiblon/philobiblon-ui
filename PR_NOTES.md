Causa real: `frontend/Dockerfile` no copiaba `yarn.lock` antes de `yarn install`, así que el build de Docker resolvía `wikibase-edit` en fresco contra el rango `^8.1.0` de `package.json` en vez de respetar la versión fijada (8.1.0) — y en el momento del build eso cayó en la **8.2.0**, recién publicada, que añadió validación estricta de `credentials.oauth` (exige `consumerKey`/`consumerSecret`/`tokenSecret`/`token`, antes no exigidos). `frontend/stores/auth.js` solo manda `{ token }` a propósito, porque la firma OAuth real la hace el backend (`WikibaseOAuthServiceImpl`), que ignora/re-firma lo que llega del cliente — así que la 8.2.0 rompe **toda** la escritura de la app (creación y edición de cualquier ítem), no solo MAN/P329. Fix: PR con `COPY package.json yarn.lock .yarnrc.yml ./` + `yarn install --immutable` en el Dockerfile, para que el build sea reproducible y respete el lockfile. **Pendiente**: si algún día se quiere subir `wikibase-edit` a ≥8.2.0 a propósito, `auth.js` tendrá que mandar también `consumerKey`/`consumerSecret`/`tokenSecret` (placeholders, no secrets reales — el backend los ignora igualmente). |
